# Object Library: создание объектов

Статус: контракт базовой Object Library реализован на C++23. Основан на
[списке объектов](objects.md) и [границах подсистем](subsystem_interaction.md).
Ревью выполнено по workflow `software-design-review`: требования, контракты,
альтернативы, ошибки и проверка. Сокращённые примеры ниже показывают два типа
из полного каталога. [Использование и ограничения реализации](objectlib_usage.md).

Структура типов, их владение и операции показаны в
[UML-диаграммах классов Object Library](objectlib_class_diagram.md).

## 1. Выбор паттерна

Использовать типизированную фабричную функцию с отображением
`ObjectType → Params → Object` через traits. Конкретные типы самостоятельно
реализуют свои правила создания и валидации; общий вход только направляет вызов.

| Вариант | Оценка для Object Library |
|---|---|
| Конструкторы конкретных типов | Достаточны для простых типов; удобно, если все входы допустимы или принята политика исключений |
| Типизированная фабричная функция | Подходит для единого API и явного результата валидации; выбранный вариант |
| Фабрика с виртуальным Factory Method | Полезна при переопределении создания через наследование; таких требований пока нет |
| Abstract Factory | Создаёт согласованные семейства реализаций; сейчас нет такой задачи |
| Builder | Может пригодиться для пошаговой сборки сетки или сложного описания; не нужен для всех объектов |

`createObject<ObjectType::Sphere3>(params)` — статический выбор операции. Это
фабричная функция; вводить иерархию классов-фабрик ради названия паттерна не нужно.

## 2. Ревью исходного API

Предложение: `createObject<objectType>(geometryParams)`.

| Вопрос | Риск | Уточнение |
|---|---|---|
| Что такое geometryParams? | Общий контейнер чисел позволяет передать параметры другого объекта | Отдельная структура параметров для каждого конкретного типа |
| Что возвращается? | Универсальный базовый указатель теряет информацию о конкретном результате | `std::expected<ConcreteObject, CreateError>` |
| Как различать 2D и 3D? | `Point`, `Polyline`, `Mesh` не определяют размерность | Явные типы и теги: Point2 / Point3, Polyline2 / Polyline3 |
| Тип выбран в редакторе | Значение enum известно во время выполнения и не может быть аргументом шаблона | Отдельный runtime-вход с типизированным variant описаний |
| Создание возвращает сетку? | Даже создание радиуса сферы запускает дорогую генерацию | Создание описания и тесселяция — разные операции |
| Кто регистрирует объект? | Фабрика начинает владеть сценой и выдавать Scene ObjectId | Object Library возвращает геометрическое значение; Core хранит экземпляр и назначает ID |
| Что означает успех? | Некорректные параметры создают объект с нарушенными инвариантами | Успех означает выполнение контракта конкретного типа; ошибка не меняет сцену |

## 3. Предлагаемый статический API

Ниже эскиз публичного заголовка. Геометрические классы `Point2`, `Sphere3` и
`Polyline2` предполагаются определёнными в своих заголовках. Enum содержит только
два примера; полный набор добавляется по мере реализации типов.

```cpp
#include <expected>
#include <variant>
#include <vector>

namespace objectlib {

enum class ObjectType {
    Sphere3,
    Polyline2,
};

struct Sphere3Params {
    double radius;
};

struct Polyline2Params {
    std::vector<Point2> vertices;
    bool closed = false;
};

enum class CreateErrorCode {
    NonFiniteParameter,
    InvalidRadius,
    TooFewVertices,
};

struct CreateError {
    CreateErrorCode code;
};

template<ObjectType kind>
struct ObjectTraits;

template<>
struct ObjectTraits<ObjectType::Sphere3> {
    using Params = Sphere3Params;
    using Object = Sphere3;
};

template<>
struct ObjectTraits<ObjectType::Polyline2> {
    using Params = Polyline2Params;
    using Object = Polyline2;
};

template<ObjectType kind>
concept SupportedObject = requires {
    typename ObjectTraits<kind>::Params;
    typename ObjectTraits<kind>::Object;
};

template<ObjectType kind>
    requires SupportedObject<kind>
[[nodiscard]]
auto createObject(typename ObjectTraits<kind>::Params params)
    -> std::expected<typename ObjectTraits<kind>::Object, CreateError>;

} // namespace objectlib
```

Пример использования:

```cpp
auto result = objectlib::createObject<objectlib::ObjectType::Sphere3>(
    objectlib::Sphere3Params{.radius = 2.0}
);

if (!result) {
    // Передать result.error() вызывающему коду / интерфейсу.
} else {
    // *result — Sphere3; Core может сохранить её в сцене.
}
```

Параметры принимаются по значению: небольшие описания копируются, массивы можно
переместить через `std::move(params)`. При передаче lvalue с массивом происходит
копирование. На выходе объект сам владеет своими данными; ссылка на временные
входные параметры не сохраняется. Для объектов с разделяемой геометрией можно
позднее определить отдельные описания с явным совместным владением.

Неверная пара enum / Params отвергается компилятором. Для этого структуры
параметров разных фигур не должны иметь неявных взаимных преобразований.
Не следует использовать `std::any`, `void*`, универсальный массив чисел или
вариадический forwarding всех возможных конструкторов в качестве основного API.

Реализация может делегировать в `Sphere3::create(params)` и аналогичные операции
конкретных типов. Шаблонная оболочка находится в заголовке; алгоритмы проверки
и создания конкретных объектов могут находиться в `.cpp`.

## 4. Выбор типа во время выполнения

Для команд редактора тип известен во время выполнения. В этом случае описание
содержит конкретную альтернативу variant, которая одновременно задаёт тип и
параметры. В отдельном enum рядом с variant необходимости нет.

```cpp
using ObjectSpec = std::variant<Sphere3Params, Polyline2Params>;
using Geometry = std::variant<Sphere3, Polyline2>;

[[nodiscard]]
auto createObject(ObjectSpec spec)
    -> std::expected<Geometry, CreateError>;
```

Runtime-перегрузка посещает выбранную альтернативу и делегирует той же статической
фабрике. Правила валидации не дублируются. Результат — конкретный геометрический
объект внутри variant; Scene ObjectId по-прежнему выдаёт Core.

Нельзя использовать `createObject<selectedType>(params)`, если selectedType —
обычная переменная, выбранная пользователем. UI преобразует выбор в соответствующее
описание `ObjectSpec`. Если enum всё же приходит из файла или другого внешнего
источника, слой декодирования проверяет его и строит описание нужной альтернативы.
Внутренние порядковые значения enum не становятся автоматически стабильным
форматом сериализации.

Публичный enum задаёт закрытый каталог типов. Добавление типа требует обновления
каталога, traits и runtime-диспетчеризации. Это приемлемо для текущей библиотеки;
поддержка сторонних типов без изменения каталога потребовала бы другого контракта.

## 5. Валидация и гарантии

- Sphere3: конечный радиус строго больше нуля; центр локального описания — начало
  координат. Размещение экземпляра задаётся преобразованием в Core.
- Polyline2: конечные координаты; в начальном контракте минимум две точки для
  открытой и три для замкнутой полилинии. Последняя точка не обязана дублировать
  первую, замыкание задаёт флаг. Самопересечение полилинии само по себе допустимо.
- Для остальных типов правила определяются отдельно: ненулевое направление
  луча, корректные индексы сетки, правила вырожденных фигур и топологии полигонов.
  Один универсальный валидатор всех геометрий не заменяет эти контракты.
- CreateError описывает ошибки геометрических данных. Выделение памяти в первой
  версии может бросать `std::bad_alloc`; `expected` не означает автоматически
  отсутствие всех исключений. Общая фабрика не объявляется `noexcept`.
- Если требуется гарантировать инварианты созданного класса, его поля закрыты,
  а операции изменения проверяют новые значения. Публичный агрегат с изменяемым
  радиусом гарантирует только проверку в момент вызова фабрики.
- Локальные счётчики ID, глобальное хранилище и запуск потоков фабрике не нужны.
  Одновременные вызовы безопасны для независимых входных данных при отсутствии
  скрытого изменяемого общего состояния.

## 6. Связь с асинхронностью

`createObject` создаёт геометрическое описание синхронно. Тяжёлая генерация
`tessellate(object, options)` является отдельной операцией; вызывающий слой может
запустить её в задаче на стабильном снимке объекта.

Если позже появится async-адаптер, он использует те же Params и тип результата,
но дополнительно фиксирует исполнитель, отмену, владение входом и доставку ответа.
Создание описания, создание экземпляра сцены и подготовка сетки не объединяются
в одну неявную асинхронную операцию.

## 7. Альтернатива без явного enum в вызове

Можно выбрать перегрузки `createObject(Sphere3Params)` и
`createObject(Polyline2Params)`: тип уже определяется параметрами. Это сокращает
дублирование и удобно, если публичный каталог enum не нужен вызывающему коду.

Для предложенного пользователем интерфейса сохраняется явный
`createObject<ObjectType::Sphere3>(Sphere3Params{...})`. Его преимущество — единая
явная точка выбора типа; цена — каталог и traits. Поддерживать одновременно
несколько статических способов вызова с одинаковым назначением на старте не нужно.

## 8. Проверки при реализации

1. Sphere3 + Sphere3Params компилируется и даёт `expected<Sphere3, CreateError>`;
   Sphere3 + Polyline2Params не компилируется.
2. Неподдерживаемый тег не удовлетворяет SupportedObject.
3. Нулевой / отрицательный радиус, NaN и бесконечность возвращают предусмотренную
   ошибку; допустимый радиус сохраняется без скрытой тесселяции.
4. Объект с массивом остаётся действительным после уничтожения Params.
5. Статический и runtime-вход одинаково принимают и отвергают одни и те же данные.
6. Ошибка фабрики не регистрирует объект в Core и не меняет сцену.

Пункты 1–5 проверяются тестами реализации; Core пока не реализован, а его
регистрация объектов находится вне этой библиотеки. Пример заголовка выше
иллюстрирует контракт; полный каталог и namespace huynity::objectlib находятся
в публичных заголовках engine/objectlib/include.
